## 0. 一句话定义

一个**本地运行、可复现、可解释**的古典中文取名引擎：从 CBDB、中文人名语料库、古诗词与公开字表中学习姓名分布，按时代/性别/风格/阶层生成「姓 ＋ 名（＋ 可选字辈）」，并通过 CLI、本地 HTTP 与 TypeScript SDK 为修仙、历史题材项目服务。

设计目标：**单名 P95 < 5 ms、1000 个名字零重复、同 seed 完全可复现、默认零生僻字、输出带解释与授权标记。**

## 1. 核心决议

| # | 决议 | 说明 |
|---|---|---|
| 1 | **不做运行时 LLM** | 本地、离线、可复现、零 API 成本；LLM 只在离线扩充词典/审校时用，不进入生成链路 |
| 2 | **数据与引擎分离** | 引擎不硬编码数据；一切词表、统计、模板走版本化 pack ＋ manifest |
| 3 | **统计 ＋ 规则 ＋ 人工词典** | 不做端到端模型；每个分数可解释、可调试、体积可控 |
| 4 | **名与字辈分开建模** | 字辈是名的一个可选约束，不单独成层；v0.6 起不再生成字 |
| 5 | **种子按人物派生** | 每个 NPC 用稳定 ID 派生 seed；批量默认 `seed_i = H(seed, i)`；增删不影响其他人 |
| 6 | **默认只用常用字表** | 可读性优先；M1 以 GB2312 一级＋二级（6,763）代理，目标通用规范一级＋二级（6,500）；表外字需显式 `allowRare` |
| 7 | **授权分层** | core 保留为 CNC/seed/公版数据分层；CBDB pack 仅个人本地构建、不随包分发；本项目不规划商用 |
| 8 | **不做命理** | 没有八字/五行/五格/生肖；避免伪科学暗示 |
| 9 | **批量双模式** | `stable` 独立 seed / `diverse` MMR ＋ 配额；解决「一千个 NPC 像一家人」与「读档名字变了」两种诉求 |
| 10 | **输出必须带解释与授权** | 每个字至少一个来源；每条结果带 license/provenance |
| 11 | **字辈用模板 ＋ 用户输入** | 不做宗谱推断；内置明皇室 ＋ 2 个通用模板；字辈字固定，另一字生成 |
| 12 | **扩展命名共用引擎、分开模块** | 宗门/功法/法宝/丹药走 `NameKind` 插件，不与人名评分混用 |

## 3. 目标与非目标

### 3.1 目标（P0）

1. 本地可跑：CLI、HTTP、TS SDK 三种形态，运行时零网络；平台限定 Web/Node。
2. 生成完整：姓 ＋ 名（1–2 字，可选字辈）。
3. 可控：时代、性别、风格、阶层、姓氏、字数、字辈、克制度、种子。
4. 可复现：同 seed ＋ 同 profile ＋ 同 pack ＝ 字节级一致。
5. 可解释：每字有读音、字义、来源；字辈有出处。
6. 可批量：1000 个名字零重复；`diverse` 模式有姓氏/首字/末字配额。
7. 可读：默认零生僻字、零不雅谐音、零 unpinned 多音字。
8. 可集成：JSON schema 稳定；HTTP 本地；TS 类型完整。
9. 可合规：core/CBDB 双包；个人自用；输出带 license/provenance。

### 3.2 非目标（本期不做）

- 八字、五行、三才五格、生肖宜忌
- 大模型实时生成 / 在线 API
- 账号、云同步、付费
- 现代英文名、日文名、韩文名
- 号（自号/别号/道号/法号/诨号/封号）
- 地名、洞府命名
- 完整 CBDB 查询前端
- 历史考据级真实性保证
- 现实政治人物、敏感人物姓名
- 避讳（国讳/家讳）
- 默认中古音/平水韵校验（P1 可选）；方言读音不做
- Unity/Godot 原生包、移动原生 SDK

## 5. 核心工作流

```
选 profile
  → 采样姓氏（时代 × 阶层 × 地域）
  → 采样名（字级过滤 → 双字搭配 → 音形义打分）
  → 校验（重名/谐音/生僻/多音/字数）
  → 输出（解释 ＋ seed ＋ license）
```

批量的额外步骤：

```
for i in 0..count-1:
    seed_i = H(seed, i)
    name_i = generate(profile, seed_i)
    if mode == diverse:
        apply MMR + quotas
    if duplicate: reroll later item (up to 5 times)
sort by index
```

## 6. 系统需求拆解

### 6.1 命名对象模型

```ts
interface PersonName {
  schemaVersion: '1.0'
  fullName: string
  surname: NameChar
  given: NameChar[]           // 1–2
  generation?: GenerationInfo
  styleTags: StyleTag[]
  era: Era
  gender: Gender
  class: SocialClass
  score: number
  warnings: Warning[]
  seed: number
  profileHash: string
  pack: Record<string, string>
  license: string
  provenance: string[]
}
```

```ts
interface NameChar {
  text: string
  pinyin: string
  tone: 1 | 2 | 3 | 4 | 0   // 0 = 轻声
  meaning?: string
  sources?: string[]
}

interface GenerationInfo {
  char: string
  index: number
  preset?: string
  poem?: string
  position: 'first' | 'second'
}
```

约束：

- `fullName = surname.text + given.map(c => c.char).join('')`
- 姓 ＋ 名总字数 ≤ 8（最多 6 字长姓 ＋ 双名）
- 字单独字段，不拼进 `fullName`
- `given.length` ∈ {1, 2}
- `warnings` 不阻断输出；硬错误用 error 返回

#### 6.2.3 ETL 步骤

1. **抽取**：SQLite 只读打开；按表分块读，不一次性 load 全库；所有查询固定 `ORDER BY`，避免行序影响聚合。
2. **清洗**：去空白/控制字符；繁简归一（OpenCC，保留原文）；剔除拉丁/数字/符号；姓名长度 2–8（含满/蒙 3–6 字长姓）。
3. **姓氏识别**：复姓表最长匹配；失败取首字；无法识别则丢弃并计数。
4. **朝代归一**：映射到 `qinhan/weijin/tangsong/mingqing/xianxia`；原始细分朝代在数据层保留，生成层归并为五档。
5. **性别归一**：`c_female` 1/0；unknown 不进入性别统计，但进入总体统计。
6. **生卒过滤**：`birth < -1000` 或 `birth > 1950` 视为异常；只影响时代统计，不删人物。
7. **聚合**：字频（总体/性别/时代/阶层）、双字共现、姓氏频率。双字共现只统计名内相邻二字，不跨姓，避免从二元组还原完整姓名。
8. **剪枝**：字频 ≥ 5；双字 ≥ 20；姓氏 ≥ 1；典故 top 20k。
9. **人工词典注入**：仙侠意象 200 字、史实/写意/宗教 300 字、负面/贬义 200 字、复姓 80、陈词 100、敏感名单 500。
10. **校验**：字表、拼音、引用完整性、权重和、无 NaN。
11. **打包**：MessagePack ＋ gzip；manifest 记录 source/version/license/SHA-256；构建时间取 `SOURCE_DATE_EPOCH`（未设置时用源数据日期），保证可复现。
12. **签名**：每个文件 SHA-256；整包 hash 写入 manifest。

#### 6.2.4 数据包与版本

| 包 | 内容 | 体积目标 | 分发 |
|---|---|---|---|
| `core` | 字、双字、姓氏、典故、黑名单 | ≤ 25 MB / ≤ 8 MB gzip | 随工具 |
| `cbdb` | CBDB 聚合 ＋ 60 万历史姓名碰撞索引 | ≤ 200 MB | 本地构建，不随包 |
| `lexicon-*` | 可选风格/题材词典 | ≤ 2 MB | 可选 |

版本规则：

- `pack.version`：内容变化即 bump；`major` 表示不兼容 schema。
- `schemaVersion`：输出结构版本。
- `code.version`：引擎版本。
- 结果里三者都记录；复现要求三者一致。

### 6.3 生成算法

#### 6.3.1 Profile

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `era` | enum | `tangsong` | 秦汉 / 魏晋 / 唐宋 / 明清 / 仙侠 |
| `gender` | enum | `any` | male / female / any |
| `style` | string[] | `[]` | 史实 / 写意 / 宗教 |
| `class` | enum | `雅士` | 俗人 / 雅士 |
| `surname` | string | 随机 | 指定姓氏；只接受 1–6 个汉字 |
| `givenLength` | auto / 1 / 2 | `auto` | 名字长度 |
| `allusion` | enum / null | `null` | 只取对应经典用典：chuci / shijing / lunyu / zhouyi / zhuangzi / tangshi / songci / all |
| `generation` | object / null | `null` | 字辈：`{ preset?, poem?, index, position, applyTo }`，见 6.3.6 |
| `restraint` | 0–1 | `0.7` | 0＝网文，1＝史传 |
| `allowRare` | boolean | `false` | 允许三级字 |
| `seed` | number / string | 随机 | 复现种子 |
| `count` | 1–10000 | `1` | 单次 `gen` 数量；`batch` 上限 100,000 |
| `mode` | enum | `stable` | `stable` / `diverse`，见 6.3.5 |
| `locale` | `zh-Hans` / `zh-Hant` | `zh-Hans` | 输出字形 |

#### 6.3.1.1 已确认的 Profile 约束

- **时代五档**：`qinhan`（秦汉）、`weijin`（魏晋）、`tangsong`（唐宋）、`mingqing`（明清）、`xianxia`（仙侠）；默认 `tangsong`。原始 CBDB 细分朝代只在数据层保留，生成层归并。
- **风格三档**：`史实`、`写意`、`宗教`。史实/写意是软约束，候选不足时回退同性别全字池；宗教是硬约束，名字必须包含对应性别的宗教字池之一（`any` 取并集）。
- **宗教字池（男 20 / 女 15）**：
  - 男：道、僧、法、德、正、元、玄、承、景、宗、真、之、弘、修、悟、子、智、贤、纯、中。
  - 女：慧、静、妙、徽、宁、清、云、灵、仙、贞、元、瑶、慈、素、如。
- **阶层两档**：`雅士`、`俗人`。雅士走默认高雅选词；俗人走通俗常见字、排行与小名式，男女尾字分开。
- **俗人锁定**：Web UI 切换俗人后禁用时代/风格/字辈；API 同样忽略 `era/style/generation`，回退默认时代、空风格、无字辈。
- **姓氏边界**：姓氏只作为固定前缀和完整姓名安全校验，不参与名用字的音形评分、风格评分或生成重掷。
- **人名黑名单**：完整姓名命中即硬排除，批量跳过，单个重掷；当前 72 条，含不雅谐音、政治人物、`吴道子`，以及伯/仲/叔/季两字组合 12 条。
- **时代姓氏**：`cbdb` pack 为每个姓氏生成 `eras` 标记（按 `c_dy` 分布）；生成时按时代取池。长姓只进入明清；秦汉/魏晋样本稀疏时补单字姓；仙侠只取 1–2 字且非“仅明清”的姓。用户手动指定长姓不受影响。
- **占位姓**：`某`、`氏` 等 CBDB 占位记录不进入姓氏池，也不能作为用户输入姓氏。
- **宗教单字名**：`中`、`子`、`之` 不作单字宗教名，避免“房中”“周子”这类弱宗教名；双字名仍可用，如子玄、道中。`房中` 另加入全名硬黑名单。
- **单字名**：`小`、`阿`、`老`、`儿`、`娘`、`姑`、`丫`、`妞`、`娃`、`妹`、`娣` 等前缀/称呼不单独作名；双字名中仍可出现，如小英、小娟。
- **雅士口语字**：雅士的名中不再出现 `大`、`小`、`丫`、`娘`、`郎`；俗人仍保留大郎、小白等口语组合。
- **时代名池**：`cbdb` pack 提供 `givenNamesByEra`；唐宋/明清各取 top 5000，魏晋取 275 条辅助池，秦汉不建双字池并回退全局。低样本时代仍保留单字名比例。
- **仙侠/写意名池**：`given-names-extra.json` 提供仙侠 52 条、写意 52 条双字名；女性另补仙侠 23 条、写意 20 条，带 `gender=female` 名级标记。仙侠优先走 `givenNamesByEra.xianxia`，写意优先走 `givenNamesByStyle.写意`；女性再优先走 `femaleGivenNamesByEra/Style`。
- **女性名池**：`cbdb` pack 可加载 MQWW 派生的 `femaleGivenNamesByEra`；当前明清 1,826 条，女性优先用该池，不足再回退时代/全局池。
- **最近姓名抑制**：Web UI 在未指定 seed 时记住最近 40 个姓名，生成时优先避开；指定 seed 时不抑制，保证复现。
- **UI 数据包/用典**：`/v1/packs` 返回本地可用包；页面可切换 seed/core/cbdb，并通过 `/v1/pack?pack=` 重建 generator。姓名页新增用典下拉，支持 chuci/shijing/lunyu/zhouyi/zhuangzi/tangshi/songci/all。
- **UI 数量/字辈序号**：姓名数量上限 10；字辈序号按模板长度限制为 1–20，前端 clamp 并在超限时提示，不再直接抛 API 错误。
- **UI 收口**：顶部显示当前 pack 状态；切换 pack/Token 时清空旧结果并重建 generator；空/错误状态统一提示；640px 以下单列布局，pack/Token 占满可用宽度。
- **UI 结构**：`web/index.html` 只保留 DOM；样式拆到 `web/styles.css`，逻辑拆到 `web/app.js`；服务端分别提供 `/styles.css` 和 `/app.js`。
- **UI 交互**：生成中禁用提交按钮并显示“生成中…”；无典故的 pack 自动禁用用典；Tab 支持 `role=tab`/`aria-selected` 与左右方向键、Home/End。
- **稀疏字辈兜底**：字辈可匹配双字名少于 8 个时，不用配对名反复填充，改为“字辈字 + 自由生成另一字”，修复 seed 下整批都是文德。
- **女性用典不依赖风格**：女性 + 用典时，无论 style 是否选“写意”，都会合并女性专属用典池；修复风格不限时只剩淑姬。
- **用户排除词**：姓名页新增“排除字词”，逗号分隔，前端过滤全名/名中包含该词的候选，并存 localStorage。
- **功能字拦截**：`blockedChars` 独立文件，雅士/普通生成拦截叹词、拟声、文言助词、疑问/程度/方位/言语动词等；`俗人` 豁免；`之/道/何/大/小/极/至/东/南/西/北/中/正/云/语/千` 为特例；`问/言/议/与/若/为/则/夫/益/愈/太` 因历史人名用例移出黑名单；姓氏路径不经过该过滤器。
- **月份**：正月—十二月、冬月、腊月加入全名黑名单。
- **不适合姓名诗句**：阳关、满天、白发、赤壁、归路加入全名硬黑名单，并从唐诗/宋词词表移除。
- **Pack 契约**：`src/core/pack.ts` 校验 pack 元数据、姓氏/字/名/时代池/女性池/风格池、典故出处和必填对象；坏包在加载时直接报 `E_PACK_INVALID`。
- **数据构建入口**：`tools/build_data.py` 固定“典故 → core → cbdb”顺序，支持 `--packs`、`--dry-run`、`--with-mqww`；npm 脚本为 `build:data`。
- **Pack 热失效**：`loadPack` 按关键数据文件 mtime/size 计算签名；重建后同一服务进程会自动重载，不需要重启才能看到新 pack。
- **CNC 女性写意补充**：从 CNC 性别语料取女性双字名，要求二字都在 seed 写意字表、排除叠字，取频次 top 120，写入 `given-names-cnc.json`；女性写意池合并后 164 条。

#### 6.3.2 姓氏采样

```
P(surname) ∝ freq_era(surname)^0.9
           × class_bias(surname|class)^1.2
           × region_bias(surname|region)^0.8
```

- 复姓概率按时代：秦汉 8%、魏晋 8%、唐宋 4%、明清 2%、仙侠 10%。
- 雅士偏置：王、谢、崔、卢、李、郑、裴、韦、杜、杨 ＋2.0。
- 俗人：常见姓/单姓为主；雅士：复姓/古姓权重略高。
- 禁止：名中出现姓字；姓与名首字同音（可选惩罚）。
- 用户指定 `surname` 只接受 1–6 个汉字；数字/字母/空格/符号报 `E_SURNAME_INVALID`。
- 字辈模式：若字辈字与姓字相同，重采样姓氏（字辈位置不动）。
- P1 前 `region_bias` 固定为 1（不做地域加权）。

#### 6.3.3 名字采样

候选字过滤：

```
level <= 2 (or allowRare)
and gender_bias in range
and era_cosine >= 0.3
and style_tag match
and not blocklist
and not surname char
# 姓—名同声母/韵母不参与评分或重掷
```

字分：

```
charScore = 0.35 * logFreqNorm
          + 0.20 * genderFit
          + 0.20 * eraFit
          + 0.15 * styleFit
          + 0.10 * readability
```

双字分（`logBigramPMI` 为双字共现的点互信息，衡量「这两个字是否真的常一起出现」）：

```
pairScore = 0.40 * logBigramPMI
          + 0.20 * charScore(c1)
          + 0.20 * charScore(c2)
          + 0.10 * toneContrast
          + 0.10 * allusionBonus
          - penalties
```

惩罚项：

| 项 | 扣分 | 说明 |
|---|---|---|
| 同字重复 | -∞ | 除非显式允许叠字 |
| 双三声 | -0.15 | 3-3 拗口 |
| 同声母 | -0.10 | 双声，非刻意 |
| 同韵母 | -0.08 | 叠韵，非刻意 |
| 同偏旁 | -0.08 | 视觉重复 |
| 总笔画 > 40 | -0.10 | 书写负担 |
| 不雅谐音 | -∞ | 直接拒绝 |
| 陈词字过载 | -0.20 | 仙侠模式 |
| 历史名人重名 | -∞ | 仅 top 10k 名人 |

采样：`softmax(score / T)`，T＝0.8；top-K＝200；不足 K 时降级。

> v0.6 实现：76 项测试通过（70 core ＋ 6 M3）；双三声/同调/同声母/同韵母/名内冲突用「最多 4 次重掷」；候选子集先打分，再 top-K（24）＋ softmax；`diverse` 批量加 MMR（λ=0.15）。风格标签来自 seed 264 字 ＋ `data/lexicons/styles.json`，`cbdb` 覆盖 364/1,815 字。偏旁/笔画已从 Unihan 18.0 导入（102,999 字），双字同偏旁/总笔画 > 40 计惩罚；楚辞/诗经/论语/周易/庄子/唐诗/宋词合并 23,524 个双字索引，命中加 0.05；全量唐诗/宋词未接入。
>
> 宗教命名由 `style=宗教` 承担，不再有 `僧道` 阶层；俗人使用通俗常见字与排行/小名式，雅士走默认高雅选词。Web UI 在俗人模式下锁定时代/风格/字辈；API 同样忽略 `era/style/generation`，统一回退到默认时代与空风格。

#### 6.3.5 批量多样性与稳定性

批量有两种模式，**不能同时承诺「全局配额/MMR」和「任意增删不影响他人」**：

| 模式 | 机制 | 稳定性 | 适用 |
|---|---|---|---|
| `stable` | 每个 item 独立 seed ＋ 字级惩罚；重复时保留最早、重掷后者 | 追加/删除末尾 item 时，其余不变 | 游戏存档、按需生成 NPC |
| `diverse` | 全局 MMR ＋ 配额 | 增删可能影响其他人 | 一次性导出 NPC 名册 |

两种模式都使用 `seed_i = splitmix64(seed ^ (i * 0x9E3779B97F4A7C15))` 作为基础种子。

`stable` 的边界：**追加或删除末尾**是稳定的；在中间插入 item 可能触发后续重复项重掷。需要任意位置稳定时，用「固定槽位 + 只重掷新 item」的调用方式，而不是重排列表。重复重掷最多 5 次；仍重复则返回 `E_NAME_COLLISION`，不静默输出重复名。

`diverse` 的细节：

- MMR（Maximal Marginal Relevance，最大边际相关）：`final = score - 0.15 * maxSim(candidate, selected)`；`sim` ＝ 字重叠 ＋ 同姓 ＋ 同声母/韵母。
- 配额（1000 个为基准）：
  - 单姓最大占比 12%；
  - 首字最大占比 10%；
  - 末字最大占比 8%；
  - 复姓最大占比 15%。
- 超配额：重采样最多 5 次；仍超则按确定性顺序放宽，并记 `warning: quota_relaxed`。
- 字辈模式下，字辈字所在位置不计入配额；配额只作用于另一个字。
- 输出按 index 排序，不按分数，保证稳定。

> 默认 `stable`：游戏项目更怕「读档后名字变了」，而不是「两个 NPC 同姓」。需要一次性名册时再切 `diverse`。

#### 6.3.6 字辈

字辈默认不启用；启用时可选明皇室、通用 A/B，或粘贴自定义诗。字辈是同一宗族、同一代共用的一个字，放在名的第一位或第二位。

> 开关：`generation=null`（默认）关闭；传对象开启。**不会因为 `era=mingqing` 自动开启**。

**内置模板**

| id | 名称 | 字辈 | 位置 | 说明 |
|---|---|---|---|---|
| `ming-imperial` | 明朝皇室（燕王系） | 高瞻祁见祐厚载翊常由慈和怡伯仲简靖迪先猷 | first | 20 字；其他藩系另有字辈 |
| `generic-a` | 通用 A | 文德承先世诗书启后贤忠孝传家远清和继泽长 | first | 项目自建，不对应真实宗族 |
| `generic-b` | 通用 B | 永绍祖泽克振家声守正崇学光启文明诗礼传家 | first | 项目自建，20 字 |

**生成规则**

1. `generation` 传 `preset` 或 `poem`，二选一；都没有则报 `E_GENERATION_INVALID`。
2. 诗去掉标点/空白，只保留汉字；长度 2–40；否则报 `E_GENERATION_INVALID`。
3. `index` 默认 1；1-based，范围 `1..len`；越界报 `E_GENERATION_INDEX`。
4. `position` ∈ {first, second}，默认 first；`givenLength` 强制 2；冲突报 `E_GENERATION_CONFLICT`。
5. 字辈字固定，写入 `given` 的对应位置；另一个字按 6.3.3 采样，双字搭配以字辈字为条件。
6. 字辈字不受 8,105 字限制（用户输入优先）；不在字表时记 `warning: generation_char_outside_table`。
7. 字辈字与姓字相同 → 重采样姓氏；仍冲突则报 `E_GENERATION_CONFLICT`。
8. 字辈字不参与首/末字配额；`diverse` 的配额只作用于另一个字。
9. 模板与时代不匹配（如宋 ＋ `ming-imperial`）→ `warning: era_mismatch`，不阻断。
10. 字辈模式 reroll 名时，只重掷非字辈字；字辈字不变。
11. 字辈只作用于名。
12. `applyTo` ∈ {all, male, female}，默认 all；不匹配时该人物不启用字辈（`generation=null`），不报错，便于混合性别批次。
13. `preset=ming-imperial` 且 `gender=female` 时，记 `warning: historical_gender_mismatch`（不阻断）；需要严格历史用法时设 `applyTo=male`。

> 明皇室模板是历史参考，不表示生成结果与明代宗室有关；其中「祐」为示字旁（朱祐樘），不是「佑」。通用 A/B 是项目自建模板，正式用请粘贴自己的字辈诗。

### 6.4 字（v0.6 移除）

v0.6 起不再生成表字（字），`courtesy` 字段、名—字配对、关系标签与字生成流程全部删除。原 `AC-35~37` 作废，编号保留。

保留的理由：字义解释与名—字配对维护成本高，且修仙/历史项目多数只需要姓名与可选字辈。后续若恢复，作为独立 `courtesy` 模块重新设计，不进入 P0。

### 6.6 确定性与种子

- PRNG：`splitmix64` ＋ `xoshiro128**`；core 中禁用 `Math.random()`。
- seed 归一：
  - number → uint64（取模 2^64）；
  - string → SHA-256 → 前 8 字节 → uint64。
- 每个 item：`seed_i = splitmix64(seed ^ (i * 0x9E3779B97F4A7C15))`（64 位无符号回绕）。
- 游戏项目建议直接用 NPC 的稳定 ID 派生 seed（`hash(worldSeed, npcId)`），不要依赖数组下标；这样插入/删除都不影响其他人。
- JSON 序列化：key 顺序固定；float 保留 6 位；UTF-8 无 BOM。
- `profileHash = SHA-256(canonical JSON(profile 去掉 seed/count/mode))`，用于记录「这组结果对应什么配置」。
- 复现条件：`seed + profile + pack version + code version` 一致。
- 数据包升级后不保证旧 seed 复现；提供 `--pack-version` 锁定。

### 6.13 扩展命名（法宝 / 宗门 / 丹药 / 功法）

结论：**结构上比人名简单，数据上比人名难。** 地名、洞府不做。

| 类型 | 结构 | 词表来源 | 难度 | 主要风险 |
|---|---|---|---|---|
| 法宝（先做） | 材质/意象/功能 ＋ 器型（剑/刀/鼎/钟/塔/印/珠/幡/镜） | 《山海经》《淮南子》＋ 人工 | 中 | 像现代物品/撞梗 |
| 宗门 | 方位/地理意象/意象 ＋ 宗/门/派/阁/殿/观/寺 | 公版古籍 ＋ 人工 | 中低 | 撞真实宗门/商标 |
| 丹药 | 功效/意象/颜色 ＋ 丹/丸/散/膏/液 | 《本草纲目》＋ 人工 | 中 | 功效与名字不符 |
| 功法 | 意象/元素/动作/程度 ＋ 动名词/空 ＋ 诀/功/真经/妙法/篇/典/章 | 诗词/道藏 ＋ 人工 | 高 | 语义空泛、陈词 |

**法宝两段式（先做）**

```
[材质/意象/功能] + [器型]
```

示例：神意＋珠；铁＋剑；赤焰＋刀；万魂＋幡；翻天＋印；澄明＋镜。2–5 字为主，不带品阶。

**功法三段式**

```
[意象/元素/动作/程度] + [动名词/空] + [诀/功/真经/妙法/篇/典/章]
```

| 槽 | 取值 | 例 |
|---|---|---|
| A | 意象 / 元素 / 动作 / 程度 | 青木、大、吐纳 |
| B | 动名词 / 空（none） | 归元、镇山、∅ |
| C | 诀 / 功 / 真经 / 妙法 / 篇 / 典 / 章 | 真经、诀、功 |

示例：青木＋归元＋真经；大＋镇山＋诀；吐纳＋∅＋功（即吐纳功）。

> `∅` 表示 B 槽为空、不生成中间字；「吐纳功」不是「吐纳无功」。

> 用户输入里的「决」按「诀」的别名兼容；输出统一写「诀」。法宝先做，法宝/功法都不加品阶；示例（神意珠、铁剑、赤焰刀、万魂幡、翻天印、澄明镜）仅作结构示意，不是默认词表。

**共用与专用**

- 共用：RNG/seed、profile、模板引擎、音形义过滤、去重/黑名单、批量模式、输出 schema、license/provenance。
- 专用：词表、模板、评分权重、校验器、材质/意象/功能/器型/功效字段。
- `NameKind` 接口：

```ts
interface NameKind {
  id: 'person' | 'sect' | 'technique' | 'artifact' | 'pill'
  generate(profile: Profile, seed: number): NameResult
  validate(candidate: NameResult, profile: Profile): Warning[]
}
```

**为什么说数据更难**

- 人名有 CBDB / CNC 的大规模真实分布；宗门、功法、法宝、丹药都没有对应的「真实语料库」。
- 网文/游戏文本有版权，不能直接抓取训练或打包；只能取公版古籍 ＋ 人工词表。
- 质量更主观：人名「像宋代」可以盲评；功法名「像修仙」很难有唯一标准。
- 陈词与撞梗更快：玄天、九转、混沌、太初、诛仙……需要 per-kind 黑名单和 novelty 惩罚。

**实施建议**

- M5 单独做，不混入 P0 的 78 条有效 AC；每类单独 AC。
- 先法宝（结构最稳、用户已定），再宗门/丹药，最后功法（语义搭配最难）。
- 不直接复用人物名的 char/bigram 权重；只复用基础设施。
- 真实宗门/功法/商标黑名单从第一天就建。
